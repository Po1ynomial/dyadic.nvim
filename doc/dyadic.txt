1. INTRODUCTION                                                 *dyadic-intro*

dyadic.nvim talks to pi (https://pi.dev) through pi's stock RPC mode
(`pi --mode rpc`). Each conversation is one pi process and one read-only
transcript buffer; a companion draft buffer is where you write input with
normal Neovim editing. There is no embedded terminal and no required UI
library.

Requirements:
- Neovim 0.11 or newer.
- `pi` on $PATH, with provider authentication and pi configuration set up.

==============================================================================
2. SETUP                                                        *dyadic-setup*

Setup is optional. Defaults:
>lua
    require("dyadic").setup({
      cmd = { "pi" },
      args = {},
      draft_height = 6,
      completion = true,
      mappings = {},
      layout = nil,
    })
<
`cmd`           Executable argv array. dyadic appends `--mode rpc`; do not
                pass another CLI mode.
`args`          Ordinary pi startup options, such as `--model` or
                `--session-dir`. Pi still loads its own configuration,
                tools, extensions, skills, and templates.
`draft_height`  Height of the draft split in the default layout.
`completion`    Set the draft's 'omnifunc' (see |dyadic-completion|).
`mappings`      Override or disable default keys (see |dyadic-mappings|).
`layout`        Function `layout(session)` that shows `session.buf` and
                `session.draft` in windows, replacing the default split.
                Use it to build floating or sidebar layouts.

Configuration applies to conversations opened afterwards. Each conversation
captures Neovim's effective cwd when it opens, including window- or tab-local
cwd, and keeps it after later |:cd| commands.

Pi's environment is Neovim's, except that an inherited `$NVIM` or
`$NVIM_LISTEN_ADDRESS` is removed. Neovim sets `$NVIM` only for |jobstart()|
and |terminal| children, so an inherited value names an outer Neovim.

3. CONVERSATIONS                                         *dyadic-conversation*

`:Dyadic` opens a conversation. The default layout puts the transcript in
the current window and the draft in a split below it. Both are scratch
buffers named `dyadic://<id>/transcript` and `dyadic://<id>/draft`; you can
show them in any windows. Windows do not own processes.

Hiding a conversation does not interrupt it. Deleting its transcript buffer
or running `:Dyadic close` ends its process and disposes its draft, detail
buffers, and pending extension dialogs. Exiting Neovim ends every pi process
dyadic started. Saved pi session files are never deleted. Deleting only the
draft leaves the conversation running; `:Dyadic show` recreates an empty
draft.

Status: the transcript window's statusline shows the title, state, model,
thinking level, context use, total tokens, cost, and extension status
entries. The same data is available from `session:status()`
(|dyadic-api|).

Notices go through |vim.notify()|. Pi's stderr goes to a temporary log file
instead; if pi exits unexpectedly, one notification gives the exit code and
the log's path.

4. TRANSCRIPT                                              *dyadic-transcript*

The transcript buffer contains only message text, so it is plain markdown.
Everything else is overlay text drawn on empty lines:

- Speaker rows: `── You`, `── Assistant · model`, extension message types.
- Activity rows: one per tool call or thinking block.
- Shell commands run with `!` or `!!`, compaction and branch summaries,
  usage entries, errors, and aborts.
- Queued steering and follow-up input, pinned to the end until pi takes it.

Activity groups                                      *dyadic-activity-groups*
Consecutive tool calls and thinking blocks form a group. Once agent text
follows a group, it collapses into one summary row, such as
`▸ thinking · 3 tools · 1 error`. A group at the end of a run stays expanded
while pi works on it, and after the run was aborted or failed. History loaded
from a saved session starts collapsed.

In the transcript, `za` toggles the group under the cursor, `K` opens the
row under the cursor in a detail buffer (or expands a collapsed summary), and
`g]` / `g[` jump between speakers. Off a row, `za` and `K` keep their native
behavior.

Detail buffers                                                *dyadic-details*
Each item opens in its own scratch buffer, `dyadic://<id>/detail/<key>`,
with a filetype that fits its content: the file's type for `read` and
`write`, `diff` for `edit` diffs, `markdown` for thinking and summaries. A
header above the first line names the tool, its status, and for `bash` the
command. A detail buffer keeps updating while it is visible, so it is where
a running command's output appears. `q` closes it; hiding it wipes it.

Following output
A transcript window follows new output only while its cursor is on the last
line. Move the cursor up to read earlier messages without being moved.

Filetypes
The transcript and draft use the filetypes `dyadic` and `dyadic_input`, so
markdown ftplugins, LSP servers, and linters do not attach. Both are
registered as markdown for treesitter. To use a markdown rendering plugin,
add `dyadic` to its filetype list.

Session history follows pi's active branch and compaction boundaries. It
shows raw conversation entries, not model-only `context_edit` replacements,
and not the system prompt or extension messages marked hidden.

5. MAPPINGS                                                  *dyadic-mappings*

Defaults are buffer-local Normal-mode mappings. Insert and Visual mode keep
native Neovim keys. `:nmap <buffer>` lists the active set with descriptions.

Draft:

  Key               Action             Behavior ~
  <CR>              `submit`             Submit; steer while pi is working
  <M-CR>            `follow_up`          Submit as a follow-up
  <Esc>             `abort`              Return queued input, then abort
  <M-Up>            `dequeue`            Return queued input to the draft
  <C-l>             `model`              Select a model
  <S-Tab>           `cycle_thinking`     Cycle thinking level
  <localleader>s    `settings`           Select an RPC-supported setting
  <localleader>i    `focus_draft`        Focus the draft
  <localleader>r    `focus_transcript`   Focus the transcript

Transcript:

  Key               Action             Behavior ~
  za                `toggle_activity`    Expand or collapse a group
  K                 `details`            Open the row's detail buffer
  g]                `next_message`       Next speaker
  g[                `prev_message`       Previous speaker
  <localleader>i    `focus_draft`        Focus the draft

Actions without a default key: `thinking`, `cycle_model`, `copy`, `new`,
`resume`. Every action has a buffer-local <Plug> mapping named after it, for
example `<Plug>(DyadicSubmit)`, `<Plug>(DyadicToggleActivity)`,
`<Plug>(DyadicCopy)`.

Override or disable defaults by action name:
>lua
    require("dyadic").setup({
      mappings = {
        submit = "<leader><CR>",
        model = false,
        copy = "<localleader>y",
      },
    })
<
Critical native keys such as CTRL-O, CTRL-T, CTRL-D, CTRL-W, and CTRL-X are
not replaced. Terminal support for modified Enter and Tab varies; remap those
actions when needed.

                                                           *dyadic-completion*
In the draft, |i_CTRL-X_CTRL-O| completes slash commands at the start of the
line and paths from the conversation's cwd, including `@`-prefixed path
references. Completion plugins with an omnifunc source (such as blink.cmp's
`complete_func` or cmp-omni) use it too. Nothing from your buffers is
attached to a prompt unless you type it.

6. PI COMMANDS                                            *dyadic-pi-commands*

Type these in the draft and submit:

  `/model [provider/model or search]`  Select a model
  `/thinking [level]`                  Select a supported thinking level
  `/new`                               Start a fresh session in this buffer
  `/resume [session-file or all]`      Pick a saved session; `all` includes
                                     other working directories
  `/name [name]`                       Set or show the session name
  `/session`, `/stats`                   Show identity, file, usage, context
  `/compact [instructions]`            Compact through pi
  `/fork [entry-id]`                   Fork from a user message and restore
                                     its text to the draft
  `/clone`                             Clone the active branch
  `/export [HTML path]`                Export HTML through pi
  `/copy`                              Copy the last assistant response
  `/settings [name] [value]`           Auto-compaction, auto-retry, steering
                                     mode, or follow-up mode
  `/quit`                              Close this conversation
  `!command`                           Run a shell command; its output joins
                                     pi's context
  `!!command`                          Run a shell command; its output stays
                                     out of model context

Settings change the active pi session, not your settings files.

Extension commands, skills, and templates from pi's `get_commands` are
forwarded to pi. Input submitted during compaction is queued locally and sent
when compaction finishes. Abort returns pi's queues and that local queue to
the draft without discarding newer unsent text.

TUI-only commands are rejected locally instead of becoming prompts: tree
navigation, login and logout, reload, scoped models, share and bug
workflows, trust management, and `/hotkeys` (use `:nmap <buffer>`).

The resume picker honors `--session-dir`, `PI_CODING_AGENT_SESSION_DIR`,
project and user `sessionDir`, and `PI_CODING_AGENT_DIR`; an active session's
directory is authoritative. Metadata is cached by file size and modification
time. dyadic keeps no conversation database of its own.

==============================================================================
7. NEOVIM COMMANDS                                           *dyadic-commands*

                                                                     *:Dyadic*
:Dyadic [new]           Open another conversation and pi process.
:Dyadic show            Show the current or most recent conversation.
:Dyadic sessions        Choose among live conversations.
:Dyadic input           Focus the current conversation's draft.
:Dyadic {action}        `submit`, `follow_up`, `dequeue`, `abort`, `close`.
:Dyadic {command}       Any pi command name from |dyadic-pi-commands|, such
                        as `model` or `resume`, without touching the draft.

`:Dyadic new` creates another buffer; `/new` changes the session inside an
existing one.

==============================================================================
8. LUA API                                                        *dyadic-api*
>lua
    local dyadic = require("dyadic")
    local session = dyadic.open()   -- open a conversation
    dyadic.show(session)            -- show it with the configured layout
    dyadic.get()                    -- conversation of the current buffer
    dyadic.list()                   -- all live conversations
    dyadic.action("submit")         -- any action from |dyadic-mappings|
    dyadic.command("resume")        -- same as :Dyadic resume
<
Session fields and methods:

`session.buf`, `session.draft`  Transcript and draft buffers.
`session:submit(mode)`          Submit the draft; `mode` is nil or
                              `"followUp"`.
`session:get_draft()`,
`session:set_draft(text)`       Read or replace draft text.
`session:status()`              Table with `title`, `status`, `active`,
                              `session_id`, `session_file`, `model`,
                              `thinking`, `context` (`tokens`, `window`,
                              `percent`), `tokens`, `cost`, and `extensions`
                              (status entry strings).

==============================================================================
9. EDITOR FILES                                                 *dyadic-files*

pi changes files with its own tools. After a tool other than `read`, `grep`,
`find`, or `ls` finishes, dyadic runs |:checktime| on every loaded,
unmodified file buffer, so they follow the agent's edits. 'autoread' decides
whether reloading asks first. Buffers with unsaved changes are skipped;
Neovim warns about them at its next timestamp check.

pi reads files from disk, so save a buffer before asking about unsaved
changes.

==============================================================================
10. EXTENSIONS AND PROTOCOL LIMITS                         *dyadic-extensions*

Extension UI requests use native equivalents:

- `select`, `confirm`: |vim.ui.select()|.
- `input`: |vim.ui.input()|.
- `editor`: a floating buffer. In Normal mode `g<CR>` accepts, `q` or <Esc>
  cancels. `<Plug>(DyadicEditorAccept)` and `<Plug>(DyadicEditorCancel)` are
  available there.
- Notifications, keyed status entries, string-array widgets (shown above or
  below the draft), titles, and editor text are applied.

Dialogs are shown one at a time. RPC timeouts and closing a conversation
cancel pending dialogs, and a late answer never sends a second response.

dyadic currently uses only stock RPC. JSONL export, deleting or renaming
saved sessions in the picker, custom extension renderers, terminal images,
custom editor components, and terminal theme controls are not available.
Images in messages are shown as text placeholders.

11. HIGHLIGHTS                                             *dyadic-highlights*

All are defined with `default = true`, so colorschemes and your config can
override them.

  DyadicTitle      Title row                  (links to |hl-Title|)
  DyadicRole       Speaker rows               (links to |hl-Title|)
  DyadicMeta       Secondary row text         (links to Comment)
  DyadicActivity   Activity and summary rows  (links to Comment)
  DyadicTool       Tool names                 (links to Special)
  DyadicRunning    Running tools              (links to DiagnosticWarn)
  DyadicError      Errors and aborts          (links to DiagnosticError)
  DyadicQueue      Queued input               (links to DiagnosticInfo)
